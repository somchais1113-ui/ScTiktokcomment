# Phase 06 — Training & Feedback (prototype)

Feedback is local, explicit, and style-only. The store accepts approved, corrected, and rejected examples with original question/body/tags, selected tone/length/variant, note and timestamps. Corrections preserve the old output and mark it rejected. Examples are suggestions for human review, not approved technical knowledge. Search requires matched primary topic, intent and identical observed context, and uses character bigram overlap for non-exact matches. Scores are heuristic, not probabilities. Optional learnStyle uses only tone/length/variant for a single question at score >=0.8, and explicit user settings take precedence. Feedback prose and tags never enter generated captions automatically; the Phase 05 validation gate remains intact. Multi-question generation does not auto-learn style. 

Storage adapter compatible with localStorage; no cloud sync, analytics or upload. Export is JSON containing user-entered text; avoid including private details. Import validates schema, enforces size/count limits, deduplicates, and imports previously approved/corrected examples as pending local review. Rejected examples remain rejected; imports cannot override local decisions. Deletion is supported. Storage errors surface; corrupt storage does not get silently overwritten. No UI or production integration yet. Future integration should use textContent/value for user strings and expose review, delete, export/import and explicit style learning. Run node knowledge/feedback-learning.test.mjs. Tests were executed as JS functions with in-memory storage; browser localStorage and Safari not yet tested. No technical records approved and no private feedback committed.
